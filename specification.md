# specification.md — sbe-access («LogicTEAM.Доступы»)

Плагин без собственного бэкенда: работает с централизованными правами в
auth-service. Общий дизайн прав —
`docs/superpowers/specs/2026-09-09-central-permissions-design.md`.

## Авторизация

JWT приложения `access`, полученный через ЦУП:
`getService('sbe-apstore').auth.getToken('access')`. Запись реестра обязана
содержать `"appId": "access"` — по нему ЦУП разрешает выдачу токена. Само
приложение (строка в `apps` с секретом) заводится auth-service при старте.

## Эндпоинты (auth-service, группа `/auth/access/*`)

| Метод и путь | Кто может | Ответ |
|---|---|---|
| `GET /auth/access/apps` | любой с токеном | `{apps:[{app_id,name}], email, global_admin}` — приложения, где вызывающий администратор (глобальному админу — все) |
| `GET /auth/access/users` | администратор хотя бы одного приложения | `{users:[{email,last_seen_at,devices}]}` — все, кто когда-либо входил |
| `GET /auth/access/users/{email}` | администратор | `{email, roles:[{app_id,name,role,common_access}]}` — только по своим приложениям |
| `POST /auth/access/permissions` | администратор этого приложения | `{app_id,email,role}`; `role:""` — отозвать |

Отказы: 401 — нет или недействителен токен; 403 — не администратор (для списка
людей или для конкретного приложения); роль `superadmin` выдаёт только
глобальный администратор.

## Модель ролей

`viewer` < `commenter` < `editor` < `admin` < `superadmin`. Пустая роль —
персональной роли нет, действует общий доступ приложения (он настраивается в
самом плагине, а не здесь). Пустой общий доступ означает «доступа нет».

## Границы

Здесь **не** настраиваются: общий доступ приложений, права на папки и подборки
Фотобанка, группы и проекты ЛИМС, устройства и ключи пользователя. Всё это
остаётся в соответствующих плагинах и в ЦУП.
